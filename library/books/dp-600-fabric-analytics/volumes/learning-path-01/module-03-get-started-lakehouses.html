Unit 1 — Introduction

Unit này dạy gì

Vì sao Lakehouse kết hợp thế mạnh của Data Lake và Data Warehouse.

Nội dung chính trong Unit

Data Warehouse: Tập trung bảng dữ liệu có cấu trúc, SQL, joins, aggregation, KPI và lịch sử nghiệp vụ. Điển hình có FactSales, DimProduct, DimCustomer, DimDate. Dữ liệu dạng log JSON, ảnh hoặc raw files có thể không phù hợp để quản lý hoàn toàn dưới cấu trúc warehouse.

Data Lake: Lưu files linh hoạt (CSV, JSON, Parquet, PDF, images). Cấu trúc có thể thay đổi theo nguồn, hữu ích khi cần lưu raw data và phục vụ Spark/ML. Tuy nhiên, thư mục files thuần túy không tự có transaction log, schema enforcement hoặc SQL table semantics.

Lakehouse: Kết hợp file storage và Delta tables. Fabric Lakehouse sử dụng OneLake cùng Spark và SQL analytics endpoint. Nó phù hợp khi vừa cần giữ raw files vừa chuẩn hóa chúng thành các bảng phân tích.

Ví dụ: Dữ liệu Dataverse, SharePoint, ERP được nạp vào Lakehouse. Raw files lưu ở Files, các bảng chuẩn hóa lưu ở Tables, SQL endpoint phục vụ kiểm tra và Power BI báo cáo. Lakehouse không làm cho Warehouse trở nên lỗi thời: Fabric hỗ trợ cả hai theo workload.

Unit 2 — Describe lakehouse features and capabilities

Unit này dạy gì

Hiểu Tables/Files, cách Delta Lake bảo đảm tính nhất quán, các lớp security và ngữ cảnh dữ liệu dùng cho AI.

Nội dung chính trong Unit

Understand lakehouse design

Tables: Chứa Delta tables với schema định nghĩa các cột, data types; có thể truy vấn bằng Spark và T-SQL từ SQL analytics endpoint. Ví dụ Tables/dbo/sales, Tables/dbo/customers.

Files: Chứa raw/staging/historical files như Files/raw/sales.csv, Files/documents/invoices.pdf. File CSV dưới Files có thể preview, nhưng không tự động là SQL table.

Lakehouse: BusinessAnalytics
├── Tables
│   └── dbo
│       ├── sales
│       ├── products
│       └── customers
└── Files
    ├── raw/sales.csv
    ├── raw/customers.json
    └── documents/invoices.pdf

Một lợi ích của việc lưu raw files là có thể xử lý lại ETL khi đổi logic nghiệp vụ. Dữ liệu được nạp sang Tables giúp các query engines làm việc theo schema ổn định.

Understand Delta Lake tables

Bảng Delta thường có nhiều file Parquet và thư mục deltalog chứa metadata/giao dịch:

sales/
├── part-00001-...snappy.parquet
├── part-00002-...snappy.parquet
└── _delta_log/
    ├── 00000000000000000000.json
    └── 00000000000000000001.json

ACID:

Thuộc tínhÝ nghĩa
AtomicityGiao dịch commit hoàn toàn hoặc không
ConsistencyBảo vệ các quy tắc nhất quán của bảng theo engine
IsolationKiểm soát truy cập/giao dịch đồng thời
DurabilityGiao dịch đã commit được duy trì

Schema enforcement: Cột Quantity kiểu Integer sẽ không nhận văn bản không chuyển đổi được. Nó không tự ngăn mọi sai lệch nghiệp vụ như Quantity âm nếu không có rule bổ sung.

Time travel: Có thể đọc một phiên bản bảng trước đó khi Delta log và files còn trong thời hạn retention. Ví dụ Spark SQL:

SELECT * FROM dbo.sales VERSION AS OF 1;

Đây là Spark SQL Delta syntax, không phải T-SQL của Lakehouse SQL analytics endpoint.

Updates/deletes: Delta Lake hỗ trợ UPDATE, DELETE, MERGE qua engine ghi phù hợp. Ví dụ Spark SQL:

UPDATE dbo.sales
SET Quantity = 5
WHERE SalesOrderNumber = 'SO1001';

Câu trên không được dùng để sửa Delta table qua Lakehouse SQL analytics endpoint, vì endpoint đó là read-only đối với underlying Delta data.

Batch và streaming: Delta tables có thể tham gia cả batch pipelines và streaming workloads được hỗ trợ. Cần thiết kế concurrency, schema và freshness phù hợp; không mặc nhiên nhiều writers đều được phép ghi tùy ý.

Manage lakehouse access
  • Workspace Roles: Admin, Member, Contributor, Viewer. Kiểm soát phạm vi cộng tác trong workspace.
  • Item-level sharing: Cấp quyền vào một Lakehouse cụ thể thay vì trao quyền rộng cho toàn bộ workspace.
  • Row-level Security (RLS): Ở SQL query surface, hạn chế dòng được SELECT; ví dụ Sales South chỉ xem Region South.
  • Column-level Security (CLS): Chặn quyền truy cập cột nhạy cảm như CustomerEmail.
  • Schema-level permissions: Quản lý quyền theo sales, finance, hr schema trong trường hợp được hỗ trợ.
  • Sensitivity labels / Purview governance: Phân loại dữ liệu và hỗ trợ tuân thủ.

Giới hạn đặc biệt: SQL endpoint RLS/CLS không tự động áp dụng lên mọi đường đọc OneLake/Spark. Khi dùng Direct Lake cần xem cách kết nối và cơ chế bảo mật thực tế, không coi security của một engine là global security.

Build a foundation for intelligent analytics

Lakehouse có tên bảng/cột, data types, business semantics rõ ràng sẽ giúp Semantic Model, Copilot và data agents làm việc hiệu quả hơn. Ví dụ NetRevenue với định nghĩa rõ thuế/chiết khấu tốt hơn một cột Amount1 không có mô tả. Fabric IQ/ontology có thể đưa thêm quan hệ nghiệp vụ trong những cấu hình hỗ trợ; AI không thay thế schema, dữ liệu đúng và access control.

Unit 3 — Ingest and transform data in a lakehouse

Unit này dạy gì

Tạo Lakehouse, ingest và chuyển đổi dữ liệu bằng công cụ đúng nhu cầu, sử dụng Shortcuts khi cần tham chiếu dữ liệu.

Nội dung chính trong Unit

Create and explore a lakehouse

Fabric portal → Workspace → New item → Lakehouse. Một Lakehouse mới hiện thường bật schema support, với schema ban đầu dbo. Một số Lakehouse legacy có cấu trúc không schema, nên không được giả định tất cả đối tượng cũ đã cùng chuẩn.

EnterpriseAnalytics
├── Tables
│   ├── dbo/audit_events
│   ├── sales/orders
│   └── finance/expenses
└── Files/raw

Lakehouse explorer: Tables/Files, upload, Shortcuts, previews, reference Lakehouses. SQL analytics endpoint: read-only T-SQL trên Delta tables, có thể tạo các SQL metadata objects như views trong phạm vi hỗ trợ. Reference Lakehouse trong explorer không tự tạo Shortcut/copy.

Trong Spark SQL có thể sử dụng namespace dạng workspace.lakehouse.schema.table ở những trường hợp hỗ trợ; ví dụ:

SELECT *
FROM SalesWorkspace.SalesLakehouse.sales.orders;
Ingest data into a lakehouse
Phương thứcKhi chọnVí dụ
UploadNạp file mẫu nhỏ/thủ côngUpload sales.csv vào Files
Load to tablesCSV/Parquet thành Delta table không viết codeFiles/data/sales.csv → Tables/dbo/sales
Dataflows Gen2Low-code Power QueryChuẩn hóa types, deduplicate, filter

Upload không đồng nghĩa Load to Tables. Một file ở Files phải được load/chuyển đổi phù hợp để trở thành Delta table có thể query qua SQL endpoint.

Ví dụ PySpark đọc CSV:

from pyspark.sql import functions as F

df = (
    spark.read.option("header", "true")
    .option("inferSchema", "true")
    .csv("Files/data/sales.csv")
)

df_clean = (
    df.filter(F.col("Quantity") > 0)
      .withColumn("Revenue", F.col("Quantity") * F.col("UnitPrice"))
)

display(df_clean)

inferSchema thuận tiện để minh họa, nhưng production nên định nghĩa data types rõ nếu input không ổn định. Nếu muốn ghi Delta cần thêm bước write.format('delta') với chế độ, đường dẫn/bảng và quyền chính xác, không phải code ở trên tự ghi.

Access data using shortcuts

Shortcut ở Files tham chiếu file/folder, ở Tables có thể tham chiếu Delta table. Schema Shortcut có thể tham chiếu nhóm nhiều Delta tables trong schema hỗ trợ, thay vì tạo từng table shortcut. External Shortcut tới ADLS/S3 phù hợp khi muốn dùng dữ liệu nguồn mà không copy thông thường. Permissions phụ thuộc passthrough/delegated identity và ACL ở nguồn.

Ví dụ: Finance muốn tham chiếu cả schema sales gồm nhiều bảng trong Lakehouse khác. Schema shortcut (nếu được hỗ trợ tại nguồn/đích) giúp giảm việc tạo nhiều table references độc lập.

Transform data in a lakehouse
  • Notebook: PySpark, Spark SQL, Scala được hỗ trợ; logic nhiều bước, xử lý quy mô lớn, reusable code.
  • Dataflows Gen2: Power Query low-code với các bước biến đổi phổ biến.
  • Pipeline: Điều phối chạy Notebook/Dataflow và các hoạt động copy/validate/schedule.

Một luồng production hợp lý: Ingest raw vào Files/raw → Notebook chuẩn hóa → ghi Delta tables → SQL endpoint kiểm tra → Power BI dùng semantic model. Không gượng ép dùng cả ba công cụ nếu chỉ cần một bước đơn giản.

Exam notes

  • CSV + no code + create Delta → Load to tables.
  • Power Query-style transformations → Dataflow Gen2.
  • Spark transformations / Python → Notebook.
  • Schedule / orchestrate tasks → Pipeline.
  • Use outside data without copy → Shortcut.

Unit 4 — Query and analyze lakehouse data

Unit này dạy gì

Phân biệt SQL analytics endpoint, Lakehouse Query Explorer, Spark Notebook và Power BI/Direct Lake.

Nội dung chính trong Unit

Query data using the SQL analytics endpoint

Mỗi Lakehouse được cung cấp SQL analytics endpoint, cho phép T-SQL SELECT, JOIN, GROUP BY trên Delta tables. Ví dụ:

SELECT Item, SUM(Quantity * UnitPrice) AS Revenue
FROM dbo.sales
GROUP BY Item
ORDER BY Revenue DESC;

Có thể tạo SQL Views theo phạm vi hỗ trợ:

CREATE VIEW dbo.vw_ProductRevenue AS
SELECT Item, SUM(Quantity * UnitPrice) AS Revenue
FROM dbo.sales
GROUP BY Item;

View là metadata/query definition, không ghi lại Delta table. UPDATE, DELETE, INSERT, MERGE trực tiếp vào underlying Delta tables không được hỗ trợ qua SQL analytics endpoint.

Explore data using Lakehouse Query Explorer

Lakehouse Query Explorer chạy Spark SQL, không phải T-SQL engine. Có syntax highlighting, IntelliSense, tabs, inline charts, export, cross-schema/cross-lakehouse, Spark SQL DML khi có quyền và bảng hỗ trợ.

Nhu cầuT-SQL analytics endpointSpark SQL Query Explorer
Đọc Delta tablesCóCó
T-SQL TOPCóKhông phải cú pháp Spark SQL chuẩn
Spark SQL LIMITKhông phải cú pháp T-SQL chuẩnCó
UPDATE underlying DeltaKhôngCó, khi hỗ trợ/quyền phù hợp
PySpark / PythonKhôngKhông; cần Notebook
Query scheduling trực tiếpKhông phải trọng tâmKhông

Ví dụ:

-- T-SQL
SELECT TOP 5 * FROM dbo.sales;

-- Spark SQL (chạy riêng trong Spark Query Explorer)
SELECT * FROM dbo.sales LIMIT 5;

Giới hạn Query Explorer được học: query tabs không được lưu bền vững như notebooks, không phải công cụ lịch chạy/phát triển Python, không có persistent query history đầy đủ hoặc cộng tác chỉnh sửa cùng lúc như một IDE chuyên biệt.

Query data using Spark notebooks

Notebook có cell Python, Spark SQL và API Spark:

%%sql
SELECT Item, SUM(Quantity) AS TotalQuantity
FROM dbo.sales
GROUP BY Item;

Hoặc PySpark:

from pyspark.sql import functions as F

result = (
    spark.table("dbo.sales")
    .groupBy("Item")
    .agg(F.sum("Quantity").alias("TotalQuantity"))
    .orderBy(F.desc("TotalQuantity"))
)
display(result)

Notebook phù hợp khi cần Python libraries, nhiều cell, transformations phức tạp hoặc được chạy bởi Pipeline. Với câu truy vấn ngắn, Query Explorer thường nhẹ hơn về workflow; với ETL code, Notebook thích hợp hơn.

Analyze and visualize with Power BI

Power BI có thể kết nối Lakehouse và xây semantic model gồm tables, relationships, measures, descriptions và security. Ví dụ DAX:

Total Revenue =
SUMX(
    FactSales,
    FactSales[Quantity] * FactSales[UnitPrice]
)

Storage modes:

ModeCách hoạt động
ImportNạp dữ liệu vào semantic model và refresh
DirectQueryGửi query xuống source lúc cần
Direct LakeĐọc Delta-Parquet qua OneLake và nạp cột cần thiết để trả lời truy vấn

Direct Lake on OneLake không có DirectQuery fallback. Direct Lake on SQL có thể fallback ở tình huống hỗ trợ, đặc biệt liên quan SQL endpoint metadata/security. Direct Lake vẫn có memory caching, framing và những giới hạn; không phải “không bao giờ có refresh” hay “không cần permissions”.

Ví dụ: Bảng Delta FactSales lớn được semantic model Direct Lake sử dụng; report theo Product dùng DAX measures/relationships đã chuẩn hóa, còn storage mode quyết định đường đọc dữ liệu.

Exam notes

Read-only T-SQL → SQL endpoint; Spark SQL with DML → Query Explorer/Notebook; Python → Notebook; Semantic model on Delta without traditional import → Direct Lake. Luôn kiểm tra tính năng security ở đúng engine.

Unit 5 — Exercise: Create a Microsoft Fabric lakehouse

Unit này dạy gì

Thực hành tạo Workspace/Lakehouse, upload CSV, khám phá Shortcut, chuyển thành Delta table, chạy T-SQL và Visual Query.

Lab: https://microsoftlearning.github.io/mslearn-fabric/Instructions/Labs/01-lakehouse.html Dữ liệu: https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/sales.csv

Chuẩn bị

  • Portal: https://app.fabric.microsoft.com, tài khoản tổ chức.
  • Quyền tạo Workspace/Lakehouse và capacity Trial/paid hỗ trợ.
  • File sales.csv; lưu ý compute/storage có thể gây phí trên paid capacity.
  • Cleanup chỉ workspace tạo riêng để thực hành.

Các bước

1. Workspace: Workspaces → New workspace → DP600LP1M3_Lab, chọn capacity phù hợp → Apply.

2. Lakehouse: New item → Lakehouse → SalesLakehouse → Create. Quan sát Tables, Files và schema dbo.

3. Upload: Files → ... → New subfolder → data → Upload files → sales.csv. Kết quả: Files/data/sales.csv, chưa có dbo.sales.

4. Explore Shortcut: Ở Files, ... → New shortcut; xem các nguồn hỗ trợ và đóng hộp thoại. Lab này chỉ khám phá nguồn Shortcut, không yêu cầu thực tạo Shortcut, khác lab Module 2.

5. Load to Tables: menu file sales.csv → Load to Tables → New table → sales → xác nhận; refresh Tables. Xem dữ liệu trong dbo.sales, View files để nhận diện Parquet và deltalog.

6. SQL analytics endpoint: Chuyển mode SQL analytics endpoint → New SQL query:

SELECT
    Item,
    SUM(Quantity * UnitPrice) AS Revenue
FROM dbo.sales
GROUP BY Item
ORDER BY Revenue DESC;

Kết quả: doanh thu theo Item, sắp xếp giảm dần. Định nghĩa revenue ở lab đơn giản, chưa chắc khớp Net Revenue production.

7. Visual query: New SQL query → New visual query → kéo sales → Manage columns → chọn SalesOrderNumber, SalesOrderLineNumber → Transform → Group by: Group by SalesOrderNumber, new column LineItems, operation Count distinct values, column SalesOrderLineNumber. Kết quả mỗi SalesOrderNumber một dòng và số line khác nhau.

8. Cleanup: Workspace settings → General → Remove this workspace, chỉ trên lab workspace.

Unit 6 — Module assessment

Unit này dạy gì

Kiểm tra sáu năng lực: định nghĩa Lakehouse, explorer vs endpoint, Shortcut, Load to Tables, Spark notebook và Direct Lake.

Câu 1. Mô tả Lakehouse đúng nhất? A. Chỉ là relational SQL Server database; B. Chỉ là file/folder ADLS Gen2; C. Kết hợp Data Lake file storage với analytical SQL capabilities. Đáp án C. A và B chỉ mô tả một phía. Mẹo: Lake + Warehouse. Liên hệ: Unit 1–2.

Câu 2. Lakehouse explorer khác SQL endpoint? A. Explorer read-only và endpoint write; B. Explorer quản lý Tables/Files/Folders còn endpoint dùng T-SQL read-only cho Delta; C. Hai bên giống nhau. Đáp án B. A đảo ngược SQL endpoint behavior; C bỏ qua sự khác biệt về chức năng. Liên hệ: Unit 3–4.

Câu 3. Dùng dữ liệu ADLS Gen2 không copy? A. Pipeline Copy Data; B. Shortcut; C. Dataflow extract/load. Đáp án B. Hai đáp án còn lại nạp/copy dữ liệu. Liên hệ: Unit 3.

Câu 4. CSV trong Files thành Delta table không code? A. PySpark notebook; B. Load to tables; C. SQL analytics endpoint. Đáp án B. PySpark cần code, SQL endpoint không chuyển Files CSV thành Delta table. Liên hệ: Unit 3, 5.

Câu 5. Khám phá file dữ liệu bằng Apache Spark? A. Notebook; B. SQL analytics endpoint; C. Dataflow Gen2. Đáp án A. Notebook có Spark, Python. Query Explorer cũng hỗ trợ Spark SQL nhưng không nằm trong lựa chọn. Liên hệ: Unit 4.

Câu 6. Mode semantic model đặc trưng cho Lakehouse theo module? A. Import; B. DirectQuery; C. Direct Lake. Đáp án C. Direct Lake kết nối Delta-Parquet/OneLake với cơ chế riêng, không phải Import truyền thống. Liên hệ: Unit 4.
