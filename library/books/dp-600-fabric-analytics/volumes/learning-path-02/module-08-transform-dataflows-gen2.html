Unit 1 — Introduction

Unit này dạy gì

Tại sao cần Dataflows Gen2 để làm sạch/chuẩn hóa data từ nhiều nguồn trước khi ghi Lakehouse hoặc Warehouse, đặc biệt khi nhóm quen Power Query và không muốn code Spark/SQL cho mọi thao tác.

Nội dung chính trong unit

Một doanh nghiệp kết hợp Orders từ SQL Server, Product Catalog từ SharePoint, Sales CSV. Các kiểu Date/Text/Number khác nhau, null hoặc duplicates làm báo cáo sai. Dataflow tạo quy trình Extract → Transform → Load: kết nối nguồn, chọn cột, chuẩn hóa type, Remove Duplicates, Merge, tính derived columns, ghi destination. Transformation tập trung dùng chung thay vì mỗi Power BI report tự xử lý lại một cách khác nhau. Dữ liệu sạch giúp semantic models và AI agents hiểu chính xác hơn.

Unit 2 — Understand Dataflows Gen2

Unit này dạy gì

Hiểu Power Query Online-based ETL, những capability hiện có, destination/update methods, Gen1/Gen2 differences và khi nào chuyển sang Notebook/T-SQL.

What are Dataflows Gen2?

Dataflow Gen2 là managed cloud ETL trong Fabric, dùng giao diện Power Query Online và M language. Một query đọc source, định nghĩa Applied Steps và có thể được gắn data destination. Query helper chỉ để Merge/Reference có thể không cần output destination.

Nguồn on-premises thường cần On-premises Data Gateway cùng permission/credentials; các nguồn cloud phù hợp có thể kết nối trực tiếp theo connector.

Dataflows Gen2 capabilities

  1. Hundreds of connectors: SQL, SharePoint, CSV, Excel, cloud services, APIs, Lakehouse/Warehouse và các connector hỗ trợ khác.
  2. 300+ Power Query transformations: Filter, Group, Merge/Append, Pivot/Unpivot, Clean, Split, Rename, calculated columns.
  3. Multiple destinations: Nạp dữ liệu đầu ra cho các Fabric items hoặc external stores phù hợp.
  4. AutoSave/background publishing: Lưu thao tác khi tác giả làm việc; vẫn kiểm tra publish/refresh success.
  5. Schedule/automate: Manual/scheduled refresh, Pipeline activity, failure notifications.
  6. AI assistance & portability: Copilot transformation; Git/CI-CD, Public Parameters, Variable Libraries trong các phiên bản hỗ trợ.

Đổi sản phẩm: Dataflows Gen2 Classic không hỗ trợ CI/CD không còn được tạo mới từ tháng 4/2026 theo thông tin đã học. Dataflows Gen2 mới dùng phiên bản hỗ trợ Git/CI-CD; các Classic đã tồn tại có thể hoạt động và được chuyển qua Save As theo khả năng hiện hành.

Output destinations

Những destination được giới thiệu: Fabric Lakehouse, Fabric Warehouse, Azure Data Lake Storage Gen2, Azure SQL Database, Fabric SQL database, SharePoint Files, Azure Data Explorer/KQL database, Snowflake. Khả năng format/schema/update method thay đổi theo loại destination.

Replace: Thay snapshot cũ bằng dữ liệu của lần refresh mới, phù hợp bảng hiện hành như Product Catalog. Append: Bổ sung dòng mà không xóa lịch sử; không tự chống duplicate nếu batch chạy lại. Incremental Refresh: Xử lý các khoảng thời gian cần refresh dựa trên DateTime policy, thay vì nạp toàn bộ lịch sử. Không đồng nghĩa tự động thực hiện Business Key MERGE/SCD2.

Dataflow Gen2 khác Power Automate Cloud Flow: cùng có chữ Flow nhưng workload/engine khác hẳn.

When to use dataflows

Low-code team, quen Power Query/Excel/Power BI, transformation mức đơn giản đến vừa, reusable logic và load tới nhiều destinations theo cấu hình hỗ trợ.

When to consider other approaches

  • Spark Notebook: Large-scale distributed computation, Python ML, complex transformations/algorithms.
  • T-SQL: SQL-first Warehouse, stored procedures, T-SQL UPDATE/MERGE/multi-table transactions.
  • Pipeline: Orchestration nhiều activities; có thể gọi Dataflow, Notebook hoặc stored procedures.

How dataflows support the intelligent data platform

Khi CustomerName có spaces thừa, Amount là text hay OrderDate sai định dạng, Copilot/agents và BI có thể trả lời sai. Dataflows giúp chuẩn hóa schema, values, measures nền và business rules nhưng không tự tạo semantic meaning đầy đủ.

Unit 3 — Transform data with Power Query

Unit này dạy gì

Tạo Dataflow, làm việc với Queries/Applied Steps/Data Preview, xử lý Data Quality, M language, Copilot và export validation.

Create a dataflow

  • Fabric Portal → Workspace → New item → Dataflow Gen2.
  • Hoặc Lakehouse → Get data → New Dataflow Gen2 để bắt đầu với Lakehouse làm destination mặc định trong trường hợp tương ứng.
  • Power Query Editor → Get data → Connector → Authentication/Connection.

Query là logic lấy/chuyển dữ liệu; Destination là nơi kết quả được lưu. Không phải mọi query phải có output riêng.

Navigate the Power Query editor

Ribbon: Home, Transform, Add Column, View. Queries Pane: Danh sách queries và Duplicate/Reference/Load. Data Preview: Sample tại Applied Step đang chọn, không nhất thiết toàn bộ source. Query Settings: Applied Steps và Parameters. Diagram View: Xem trực quan luồng query, dependencies, steps.

Ví dụ sequence:

Source → Navigation → Removed Other Columns → Filtered Rows
      → Changed Type → Renamed Columns → Added Custom

Một bước có thể có bánh răng chỉnh cấu hình. Nếu không có, chỉnh M hoặc thay bước phù hợp.

Apply common transformations

TransformChức năngVí dụ
Filter RowsGiữ dòng hợp lệQuantity > 0
Select/Remove ColumnsGiảm số cộtGiữ Date/Customer/Amount
Change Data TypesText→Date/NumberOrderDate

Merge Queries vs Append Queries: Merge tương tự JOIN theo CustomerID; Append tương tự UNION ALL, nối các dòng của những dataset tương thích. Không dùng Append để bổ sung CustomerName từ bảng Customer theo key. Không dùng Merge để ghép các file Sales theo năm nếu schema giống nhau và mục đích là nối các bản ghi.

Pivot/Unpivot: Excel bảng cột Jan, Feb, Mar thích hợp Unpivot thành Month/Revenue để có long format dễ báo cáo. Pivot làm ngược lại; cần aggregation nếu nhiều giá trị tại cùng giao điểm.

Clean and standardize data

  • Null: Xóa, thay bằng default hoặc giữ như trạng thái hợp lệ. DeliveryDate=NULL có thể nghĩa chưa giao, không phải lỗi.
  • Remove Duplicates: Phải chọn đúng uniqueness grain; không chọn riêng OrderID nếu một Order có nhiều Lines.
  • Trim: " Contoso " → "Contoso" để tránh Merge mismatch.
  • Standardize case: hanoi/HANOI/HaNoi → HANOI nếu business rules cho phép.
  • Errors: N/A chuyển Number có thể lỗi; Remove Errors/Replace Errors hoặc M try/otherwise. Không tự thay doanh thu lỗi bằng 0 nếu cần đối soát tài chính.

Work with the M language

M là functional language; query gồm let khai báo nhiều bước, in chỉ kết quả trả về.

let
    Source = #table({"CustomerName"}, {{"  contoso  "},{"  fabrikam "}}),
    CleanNames = Table.TransformColumns(
        Source,
        {{"CustomerName", each Text.Upper(Text.Trim(_)), type text}}
    )
in
    CleanNames

Hàm dùng lại:

(inputText as text) as text => Text.Upper(Text.Trim(inputText))

Parameterized query:

Table.SelectRows(Source, each [OrderDate] >= MinimumDate)

Try/otherwise:

try Number.FromText([Amount]) otherwise null

Advanced Editor giúp xem/sửa code do UI tạo. Kết quả NULL khi lỗi chỉ là một chiến lược; nên đưa bad records vào error log nếu dữ liệu Production có yêu cầu kiểm soát.

Use Copilot for Dataflow Gen2

Từ Power Query Editor → Copilot, có thể yêu cầu “Remove rows where Status is null”, “Add Profit = Revenue - Cost”, “Group by Customer, count orders”, hoặc giải thích Applied Steps. Kiểm tra lại kết quả, business rules và datatype.

Điều kiện được giảng: paid Fabric capacity F2+ hoặc P1+, tenant Copilot enabled, supported region/cấu hình xử lý dữ liệu. Fabric Trial thông thường không hỗ trợ Copilot trong ngữ cảnh học này; lab core vẫn làm được không cần AI. Quản trị viên cần đánh giá geographic/compliance boundary trước khi bật xử lý ngoài vùng.

Export query results for validation

Queries Pane → Query → Home → Export data để kiểm tra một sample CSV/Excel theo tính năng hỗ trợ. Validation sample không thay thế full refresh QA hoặc đối soát bảng destination.

Unit 4 — Optimize Dataflows Gen2 performance

Unit này dạy gì

Giảm refresh duration/capacity consumption bằng Modern Query Evaluator, Query Folding và best practices.

Modern Query Evaluator

Engine mặc định cho Gen2 giúp xử lý phức hợp JOIN/GROUP/type conversion hiệu quả hơn. Không cần tự tạo cluster, nhưng không chữa được mọi vấn đề như overfetch, poor connectors, expensive cross-source Merge hay không folding.

Understand query folding

Folding: Đẩy một phần hoặc toàn bộ transformation về engine nguồn dữ liệu. Nếu SQL Server có 10 triệu rows và chỉ cần 100 nghìn rows năm 2026, Filter folding giúp SQL Server trả về tập đã lọc thay vì tải hết rows rồi lọc trong Power Query.

Table.SelectRows(Orders, each [OrderDate] >= #date(2026,1,1))

Có thể được chuyển sang native SQL tương đương:

SELECT * FROM dbo.Orders WHERE OrderDate >= '2026-01-01';

Ba kết quả: Full Folding, Partial Folding, No Folding. CSV/Excel thường không có SQL query engine cho Folding; SQL Server/Azure SQL và một số OData/structured sources có thể folding tùy connector/operation.

Check if a step folds

Power Query Online: chọn Applied Step → View Native Query nếu connector hỗ trợ; kiểm tra Folding Indicators và Query Plan. View Native Query bị disable không phải lúc nào cũng chứng minh không có folding. Engine có thể reorder/optimize transformations nên một step ở giữa không folding không nhất thiết là mọi bước sau vĩnh viễn không folding.

Apply folding-friendly patterns

Thường thuận lợi: Filter (WHERE), Select Columns (SELECT), Sort (ORDER BY), Group By, Merge same-source (JOIN), type casts/rename nếu connector hỗ trợ. Các thao tác như complex custom M, cross-source merges, Table.Buffer, Pivot/Unpivot phức tạp có thể phá hoặc hạn chế folding.

Filter early + Select required columns early thường hữu ích để giảm network/data size, nhưng phải giữ đúng business logic. Không bỏ cột business key cần chống trùng.

Use preview-only steps for efficient iteration

Applied Steps → Right click → Enable only in previews ở giao diện hỗ trợ. Preview-only filter giúp xem 100 dòng để debug, không áp dụng trong production refresh. Không nhầm với Incremental Refresh (chiến lược làm mới dữ liệu thực tế theo kỳ).

Follow performance best practices

  1. Filter early. Giảm rows không cần thiết.
  2. Select columns early. Giảm data size.
  3. Disable unnecessary loads. Helper queries không cần destination.
  4. Staging Dataflows. Tách landing raw và curated transform: Source → Staging Dataflow → Raw Lakehouse → Transformation Dataflow → Curated Lakehouse/Warehouse.
  5. Parameterize for reuse. Public Parameters hoặc Fabric Variable Libraries cho Dev/Test/Prod configuration ở các trường được hỗ trợ.
  6. Monitor refresh. Refresh history, Monitoring Hub, capacity use; tìm nguyên nhân từ volume tăng, poor folding, cross-source Merge, full reread, capacity saturation.

Production limitations đã thảo luận: Tối đa 50 queries có staging/destination trong một Dataflow Gen2 theo tài liệu đương thời; helper queries không load không tính cùng giới hạn. Lưu ý tên cột/bảng đặc biệt tại Lakehouse destination, gateway version, Workspace constraints và Guest cross-tenant connections. Không tự sửa/xóa internal staging items do Fabric quản lý.

Unit 5 — Exercise: Transform data with Dataflows Gen2

Lab: https://microsoftlearning.github.io/mslearn-fabric/Instructions/Labs/26b-transform-data-dataflows.html Sample CSV: https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv

Unit này dạy gì

Tạo Dataflow Gen2 kết nối CSV công khai, chọn/chuẩn hóa cột, lọc dòng, tạo Unit Price, ghi Lakehouse và kiểm tra refresh.

Chuẩn bị

  • Work/school account; Workspace với Fabric Trial hoặc Paid Capacity và quyền tạo Lakehouse/Dataflow.
  • https://app.fabric.microsoft.com; không cần Gateway cho CSV công khai, authentication Anonymous.
  • Workspace riêng DP600-LP2-DataflowsLab, Lakehouse SalesLakehouse.
  • Copilot optional cần license/tenant settings phù hợp.

Bước 1–3: Workspace, Lakehouse, Dataflow

Workspaces → New workspace → New item → Lakehouse → SalesLakehouse → Get data → New Dataflow Gen2.

Import from a Text/CSV file → Link to file → https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv → Create new connection → Authentication Anonymous → Next → Create.

Raw columns:

SalesOrderID, OrderDate, CustomerID, LineItem,
ProductID, OrderQty, LineItemTotal

Bước 4: Choose Columns

Giữ OrderDate, CustomerID, LineItem, OrderQty, LineItemTotal; bỏ hai cột còn lại trong lab. Trong Production, cân nhắc giữ SalesOrderID/ProductID nếu cần grain/reconciliation.

Bước 5: Filter Rows

  • OrderDate → Filter → Remove empty.
  • OrderQty → Number Filters → Greater Than → 0.

Bước Quantity > 0 tránh chia cho 0 trong UnitPrice, nhưng trong nghiệp vụ hoàn trả hàng, negative quantity có thể hợp lệ và không nên xóa mặc định.

Bước 6: Set Data Types

OrderDate: Date; OrderQty: Whole Number; LineItemTotal: Decimal Number. Khi là financial data Production, cân nhắc fixed decimal/precision và locale.

Bước 7: Rename Columns

OrderQty → Quantity, LineItemTotal → Line Total, LineItem → Item theo bài gốc.

Bước 8: Add Calculated Column

Add Column → Custom Column → New Column Name Unit Price → [Line Total] / [Quantity]; kết quả là đơn giá từng dòng. Khi chia phải bảo đảm Quantity != 0. Nếu Lakehouse destination không chấp nhận spaces trong tên cột, dùng LineTotal và UnitPrice ở bảng đích.

Bước 9: Review Applied Steps, Diagram, Publish

Kiểm tra Source → Promoted Headers → Choose Columns → Filtered Rows → Changed Type → Renamed Columns → Added Custom. Bật Diagram View nếu cần. Home → Save and run, theo dõi Recent runs/refresh status, kiểm tra SalesLakehouse → Tables → orders.

Bước 10: Round Unit Price, rerun, verify

Unit Price → Transform → Rounding → Round → 2 decimal places, Save and run. M tương ứng:

Number.Round([UnitPrice], 2)

M code tổng hợp minh họa

Đây là ví dụ luyện tập không chứa spaces ở tên cột đích:

let
    Source = Csv.Document(
        Web.Contents("https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv"),
        [Delimiter=",", Encoding=65001, QuoteStyle=QuoteStyle.Csv]
    ),
    Headers = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
    KeepColumns = Table.SelectColumns(Headers,
        {"OrderDate","CustomerID","LineItem","OrderQty","LineItemTotal"}),
    ChangeTypes = Table.TransformColumnTypes(KeepColumns,
        {{"OrderDate",type date},{"CustomerID",Int64.Type},
         {"LineItem",Int64.Type},{"OrderQty",Int64.Type},
         {"LineItemTotal",type number}}, "en-US"),
    FilterRows = Table.SelectRows(ChangeTypes,
        each [OrderDate] <> null and [OrderQty] <> null and [OrderQty] > 0),
    RenameColumns = Table.RenameColumns(FilterRows,
        {{"LineItem","Item"},{"OrderQty","Quantity"},
         {"LineItemTotal","LineTotal"}}),
    AddUnitPrice = Table.AddColumn(RenameColumns,"UnitPrice",
        each Number.Round([LineTotal]/[Quantity],2), type number)
in
    AddUnitPrice

Copilot Optional

Prompts: “Remove rows where OrderDate is empty”, “Add UnitPrice by dividing LineTotal by Quantity”. Kiểm tra Applied Steps. Trial không bảo đảm có Copilot.

Lỗi và cleanup

  • Connection URL/authentication sai → kiểm tra nguồn và Anonymous.
  • DataFormat.Error → kiểm tra locale, datatype và giá trị bẩn.
  • Division by zero → filter/conditional calculation.
  • Missing target table → kiểm tra refresh success và Lakehouse Explorer.
  • Destination schema spaces/unsupported characters → đổi tên columns theo hạn chế hiện hành.
  • Append duplicate → xác định update method và chống trùng.
  • Cleanup chỉ xóa Workspace lab sau khi hoàn thành.

Unit 6 — Knowledge check (5 câu)

  1. Primary purpose of Dataflow? — Low-code Extract/Transform/Load qua Power Query. Không phải Power BI visualization hoặc workspace security.
  2. Query Folding? — Push transformations xuống source engine. Không phải gộp query trong GUI hay sắp xếp Applied Steps.
  3. JOIN hai queries theo common key? — Merge Queries. Append nối rows; Group By tổng hợp.
  4. Cách kiểm tra folding trong connector phù hợp? — View Native Query ở Applied Step, kết hợp Query Plan/Folding Indicators; không chỉ đọc Advanced Editor hoặc Refresh History.
  5. Khi nào Notebook tốt hơn Dataflow? — Complex logic / large-scale distributed Spark processing. Low-code filter/rename đơn giản vẫn ưu tiên Dataflows.

Unit 7 — Summary

  • Dataflows Gen2 là low-code Fabric ETL sử dụng Power Query M, có multiple destinations và refresh/orchestration.
  • Phân biệt Merge vs Append, Pivot vs Unpivot, Type conversion, Error handling, parameters và Copilot.
  • Performance cần Query Folding, early filtering/projection, preview-only dev, staging, refresh monitoring.
  • Chọn Notebook/T-SQL khi workload yêu cầu distributed Python, transaction SQL hoặc stored procedures.
