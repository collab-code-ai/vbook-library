Unit 1 — Introduction

Unit này dạy gì

Notebook là giải pháp code-first dùng Apache Spark để transform dữ liệu lớn, phức tạp hoặc cần Python/SQL kết hợp. Module nối tiếp Dataflows Gen2 low-code và chuẩn bị tables cho Power BI/AI.

Nội dung chính trong unit

Giả sử Lakehouse có raw_sales, customers, products: duplicate rows, missing region, inconsistent column names và chưa có Revenue/Running Total. Notebook thực hiện cleaning, joins, aggregation, windows và ghi gold_sales Delta table. Spark SQL và PySpark cùng dùng Spark execution engine, nhưng cú pháp/nguồn API khác. Quy trình:

Unit 2 — Describe notebooks in Fabric

Unit này dạy gì

Hiểu Spark sessions, cell types, default Lakehouse, magic commands, multiple data stores, interactive/parameterized/pipeline patterns.

What are Fabric notebooks?

Notebook là môi trường dạng Jupyter trong Fabric có Code Cells và Markdown Cells, hỗ trợ PySpark (Python), Spark SQL, Scala, R. Spark session giữ variables/temp views khi chạy, nhưng không giữ sau khi session restart. Delta Tables ghi vào OneLake tồn tại độc lập với session.

sales_df = spark.table("raw_sales")
sales_df.limit(5).show()

Cell sau có thể dùng sales_df nếu Cell trước đã thực thi và session còn sống. Trình tự chạy rất quan trọng.

Key notebook concepts

  • Cells: Chạy từng cell với Shift+Enter; kết hợp code và Markdown mô tả business rules.
  • Lakehouse attachment: Notebook Explorer → Add data items → Add Lakehouse, đặt Default Lakehouse nếu muốn đọc spark.table("raw_sales") mà không chỉ full path.
  • Magic commands: %%sql chọn Spark SQL cho một cell; không phải T-SQL Warehouse. Có thể dùng %%pyspark cho PySpark theo môi trường hỗ trợ.
%%sql
SELECT * FROM raw_sales LIMIT 10;

Phân biệt Spark SQL chạy Spark engine và T-SQL trong Warehouse SQL Query Editor: chúng không hỗ trợ hoàn toàn cùng syntax, stored procedures hay transaction semantics.

When to use notebooks versus Dataflows Gen2

NotebookDataflows Gen2
Code-first, Python/SQL/Scala/RLow-code Power Query M
Distributed Spark transformationsManaged Power Query transformations
Complex ETL, advanced Python, huge joinsCommon preparation, SQL/CSV/SharePoint cleanup
Cần quản lý dependencies/code/logsThuận tiện cho analyst quen Excel/Power BI

Không chọn Notebook chỉ vì “mạnh hơn”; đánh đổi là công sức bảo trì code và điều hành Spark.

What data stores can notebooks access

Lakehouse (Delta native), Warehouse (read/access qua cơ chế supported, chú ý write limitations), KQL Database/Eventhouse (Kusto/Spark connectors), External sources (JDBC, ADLS, Blob, REST nếu hỗ trợ). Cần permission và connector phù hợp, không áp dụng một lệnh write cho mọi store.

Common development patterns

  • Interactive: Code → Inspect schema/rows → Debug → Transformation.
  • Parameterized: Cell Parameters, được Pipeline truyền giá trị runtime (run_date, environment).
  • Pipeline integration: Copy Data → Notebook Transform → Data Quality Check → Semantic Model Refresh. Pipeline giải quyết orchestration/dependencies/retries, Notebook xử lý transformation.
  • Copilot assistance: Có thể giúp viết/explain/debug Spark code nhưng cần kiểm chứng dữ liệu và licensing phù hợp.

Unit 3 — Shape and clean data

Unit này dạy gì

Sử dụng DataFrame API và Spark SQL để đọc, deduplicate, handle nulls, filter, select/rename, calculated/conditional columns và cast types.

Read data from a lakehouse table

df = spark.table("raw_sales")
df.printSchema()
df.show(10)
df.count()

df.filter(...) là lazy transformation, còn count()/show() kích hoạt Spark actions. Không lạm dụng collect() với dữ liệu lớn vì đưa kết quả về driver.

%%sql
SELECT * FROM raw_sales;

Remove duplicate rows

%%sql
SELECT DISTINCT * FROM raw_sales;
deduped_df = df.dropDuplicates()

Để chọn latest row by business key, không dùng dropDuplicates(["OrderID"]) nếu muốn chắc chắn record có UpdatedAt mới nhất; dùng Window:

%%sql
WITH ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (
      PARTITION BY OrderID ORDER BY UpdatedAt DESC, SequenceNo DESC
    ) AS rn
  FROM raw_orders
)
SELECT * FROM ranked WHERE rn=1;
from pyspark.sql import Window
from pyspark.sql.functions import col, row_number
w = Window.partitionBy("OrderID").orderBy(col("UpdatedAt").desc())
latest_df = orders_df.withColumn("rn", row_number().over(w)).filter(col("rn")==1).drop("rn")

Nếu nhiều rows cùng UpdatedAt phải thêm stable tie-breaker phù hợp.

Handle null values

%%sql
SELECT order_id, COALESCE(region,'Unknown') AS region,
       COALESCE(discount,0) AS discount
FROM raw_sales;
clean_df = df.fillna({"region":"Unknown", "discount":0})
required_df = df.dropna(subset=["customer_id"])

Không mọi null đều là lỗi (DeliveryDate=NULL có thể đang xử lý). Thay null bằng 0 ở Amount khi thiếu dữ liệu có thể gây báo cáo sai; cân nhắc error/unknown dimension rows.

Filter rows

%%sql
SELECT * FROM raw_sales
WHERE order_date >= DATE '2026-01-01'
  AND order_date < DATE '2027-01-01'
  AND amount > 0;
from pyspark.sql.functions import col
filtered_df = clean_df.filter(
    (col("order_date") >= "2026-01-01") &
    (col("order_date") < "2027-01-01") &
    (col("amount") > 0)
)

PySpark dùng &, |, ~ với Column expressions, đặt ngoặc từng điều kiện; Python and không thay thế cho column conjunction. Quantity âm có thể là returns, không mặc định loại.

Select and rename columns

%%sql
SELECT order_id, cust_id AS customer_id,
       prod_code AS product_id, amount
FROM raw_sales;
result_df = df.select(
    "order_id", col("cust_id").alias("customer_id"),
    col("prod_code").alias("product_id"), "amount"
)
# Chỉ đổi tên:
renamed_df = df.withColumnRenamed("cust_id","customer_id")

Add calculated columns

%%sql
SELECT *, quantity * unit_price AS line_total,
       YEAR(order_date) AS order_year,
       MONTH(order_date) AS order_month
FROM clean_sales;
from pyspark.sql.functions import year, month
result_df = (clean_df
   .withColumn("line_total",col("quantity")*col("unit_price"))
   .withColumn("order_year",year(col("order_date")))
   .withColumn("order_month",month(col("order_date"))))

DataFrames là immutable transformations về mặt API: .withColumn trả DataFrame mới; không trực tiếp ghi lại source table cho tới khi gọi write.

Create conditional columns

%%sql
SELECT *, CASE
  WHEN line_total > 500 THEN 'High'
  WHEN line_total > 100 THEN 'Medium'
  ELSE 'Low' END AS value_tier
FROM clean_sales;
from pyspark.sql.functions import when
result_df = result_df.withColumn("value_tier",
  when(col("line_total")>500,"High")
  .when(col("line_total")>100,"Medium")
  .otherwise("Low"))

Đặt điều kiện theo business threshold; phân biệt > và >= ở boundary.

Convert data types

%%sql
SELECT CAST(amount AS DECIMAL(18,2)) AS amount,
       CAST(quantity AS INT) AS quantity,
       CAST(order_date AS DATE) AS order_date
FROM raw_sales;
typed_df = (df
   .withColumn("amount",col("amount").cast("decimal(18,2)"))
   .withColumn("quantity",col("quantity").cast("int"))
   .withColumn("order_date",col("order_date").cast("date")))

Với text lỗi "unknown", cast có thể fail hoặc ra null tùy ANSI mode; Spark SQL có try_cast trong các ngữ cảnh được hỗ trợ. DECIMAL phù hợp hơn floating-point cho currency/precision cố định.

The cleaned dataset

Đầu ra mong muốn của ví dụ Unit: 11 raw rows có một duplicate → 10 unique, NULL region được xử lý, column names/types chuẩn, có LineTotal/Year/Month/ValueTier. Thứ tự bước không phải bất biến; có thể cần cast trước filter.

Unit 4 — Combine and aggregate data

Unit này dạy gì

JOIN tables, Group By, Window Functions, CTE và Pivot để tạo enriched/aggregated datasets đúng grain.

Join tables

%%sql
SELECT s.OrderID,s.Amount,c.CustomerName
FROM Sales s
INNER JOIN Customers c ON s.CustomerID=c.CustomerID;
joined_df = sales_df.join(customers_df,on="CustomerID",how="inner")

INNER chỉ match; LEFT giữ mọi dòng bên trái; RIGHT giữ mọi dòng bên phải; FULL OUTER giữ tất cả; CROSS tất cả tổ hợp. Với Fact-to-Dimension, INNER có thể làm mất orphan transactions; LEFT JOIN thuận tiện audit. Nếu dimension business key không unique, JOIN nhân bản sales rows và SUM bị thổi phồng.

Aggregate data with grouping

%%sql
SELECT Region, COUNT(*) AS OrderCount,
       SUM(Amount) AS TotalSales, AVG(Amount) AS AvgSales
FROM Sales
GROUP BY Region
HAVING SUM(Amount)>1000;
from pyspark.sql.functions import count, sum as spark_sum, avg
agg_df = sales_df.groupBy("Region").agg(
    count("*").alias("OrderCount"),
    spark_sum("Amount").alias("TotalSales"),
    avg("Amount").alias("AvgSales"))
high_df = agg_df.filter(col("TotalSales")>1000)

WHERE lọc rows trước aggregation; HAVING lọc groups sau aggregation. Group By Region làm grain thành 1 row/Region; Group By Region+Month làm grain thành 1 row/Region+Month.

Apply window functions

Window Function tính toán trong nhóm nhưng giữ rows, ví dụ Running Total per Customer:

%%sql
SELECT CustomerID,OrderID,OrderDate,Amount,
  ROW_NUMBER() OVER (
    PARTITION BY CustomerID ORDER BY OrderDate,OrderID
  ) AS OrderSequence,
  SUM(Amount) OVER (
    PARTITION BY CustomerID ORDER BY OrderDate,OrderID
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS RunningTotal
FROM Sales;
from pyspark.sql import Window
from pyspark.sql.functions import row_number
w = (Window.partitionBy("CustomerID")
  .orderBy("OrderDate","OrderID")
  .rowsBetween(Window.unboundedPreceding,Window.currentRow))
result_df = sales_df.withColumn("RunningTotal",spark_sum("Amount").over(w))

Functions: ROW_NUMBER, RANK, LAG, LEAD, SUM OVER, AVG OVER, COUNT OVER. ORDER BY nên có stable tie-breaker để tránh không ổn định khi có nhiều giao dịch cùng ngày. Window có thể cần shuffle/sort, không mặc định nhanh hơn GROUP BY.

Use common table expressions

%%sql
WITH monthly_sales AS (
  SELECT YEAR(OrderDate) AS SalesYear,
         MONTH(OrderDate) AS SalesMonth,
         SUM(Amount) AS TotalSales
  FROM Sales
  GROUP BY YEAR(OrderDate),MONTH(OrderDate)
), ranked AS (
  SELECT *, RANK() OVER (ORDER BY TotalSales DESC) AS SalesRank
  FROM monthly_sales
)
SELECT * FROM ranked WHERE SalesRank<=5;

CTE giúp chia query thành bước có tên, không tự materialize thành permanent table. RANK có ties nên lọc SalesRank<=5 có thể trả hơn năm rows.

Pivot data

%%sql
SELECT * FROM (
  SELECT Product,Quarter,Amount FROM Sales
) PIVOT (SUM(Amount) FOR Quarter IN ('Q1','Q2'));
pivot_df = sales_df.groupBy("Product").pivot("Quarter",["Q1","Q2"]).sum("Amount")

Khi biết trước quarter values nên truyền list để giảm việc Spark phải tự xác định distinct pivot values.

Unit 5 — Write and size Delta tables

Unit này dạy gì

Ghi Delta Tables vĩnh viễn, chọn mode, partition đúng, tối ưu small files và hiểu ACID/Schema Enforcement/V-Order.

Write transformed data to tables

%%sql
CREATE OR REPLACE TABLE gold_sales
USING DELTA
AS SELECT * FROM transformed_sales;
result_df.write.format("delta").mode("overwrite").saveAsTable("gold_sales")

DataFrame variable/temporary view mất khi session kết thúc; managed Delta Table trong Lakehouse vẫn tồn tại. Với schema-enabled Lakehouse dùng schema.table phù hợp.

Choose a write mode

  • Overwrite: Thay toàn bộ data cho full rebuild, cẩn thận source có đủ dữ liệu.
  • Append: Thêm rows, không tự chống duplicate khi retry.
  • MERGE: Bổ sung pattern insert/update theo business key; cần nguồn unique để không một target match nhiều source rows.
%%sql
MERGE INTO gold_sales AS target
USING staging_sales AS source
ON target.OrderID=source.OrderID
WHEN MATCHED THEN UPDATE SET target.Amount=source.Amount
WHEN NOT MATCHED THEN INSERT (OrderID,Amount)
 VALUES (source.OrderID,source.Amount);

SCD Type 2 yêu cầu historical-version logic riêng, không chỉ overwrite bằng MERGE Type 1.

Partition tables for query performance

%%sql
CREATE OR REPLACE TABLE fact_sales
USING DELTA
PARTITIONED BY (year,month)
AS SELECT * FROM transformed_sales;
result_df.write.format("delta").partitionBy("year","month") \
    .mode("overwrite").saveAsTable("fact_sales")

Partition pruning giúp tránh đọc partitions ngoài predicate nhưng over-partitioning tạo nhiều files/metadata. Hướng dẫn tham khảo trong module: xem xét partition với bảng lớn (khoảng >1 TB) có filter thường xuyên theo partition; nhắm partition đủ lớn (khoảng >=1 GB); tránh high cardinality CustomerID, Year/Month/Region thường thích hợp hơn tùy data profile.

Manage file sizes

Small-files problem: Append nhỏ liên tục khiến quá nhiều Parquet files. OPTIMIZE compact files, VACUUM dọn files cũ không còn được tham chiếu theo retention. Không nhầm hai lệnh:

%%sql
OPTIMIZE gold_sales;
%%sql
VACUUM gold_sales;

Mục tiêu file sizes tham khảo trong module là 128 MB–1 GB tùy workload. Optimize Write giúp giảm nhiều file nhỏ khi ghi. VACUUM có thể làm mất khả năng Time Travel tới versions cũ sau retention; phải xét policy/readers/rollback trước khi dùng.

Use Delta table features

  • ACID transactions: Nhất quán ở cấp Delta table; không suy ra multi-table ACID tự động.
  • Schema Enforcement: Từ chối incompatible writes; Schema Evolution chỉ khi được cấu hình/cho phép.
  • V-Order: Tối ưu layout Parquet cho read-heavy analytics/Direct Lake. Workspace mới mặc định tắt theo tài liệu đã học để ưu tiên writes; không bật mọi nơi.
spark.conf.set("spark.sql.parquet.vorder.default","true")

Cấu hình cũ spark.sql.parquet.vorder.enable không còn dùng trong Fabric Runtime 1.3+ theo nội dung đã thảo luận.

Bước 2: Shape and clean

%%sql
CREATE OR REPLACE TEMP VIEW clean_sales AS
SELECT DISTINCT
  order_id,customer_id,product_id,quantity,unit_price,order_date,
  COALESCE(region,'Unknown') AS region,
  ROUND(quantity*unit_price,2) AS line_total,
  CASE
    WHEN quantity*unit_price > 100 THEN 'High'
    WHEN quantity*unit_price > 50 THEN 'Medium'
    ELSE 'Low'
  END AS value_tier
FROM raw_sales;
%%sql
SELECT * FROM clean_sales ORDER BY order_id;

Mong đợi: 10 rows, OrderID 10 không trùng, OrderID 6 Region = Unknown, có LineTotal/ValueTier. Lưu ý threshold lab là High >100/Medium >50, không phải threshold minh họa khác trong phần lý thuyết.

Bước 3: Join and aggregate

%%sql
CREATE OR REPLACE TEMP VIEW enriched_sales AS
SELECT s.order_id,s.order_date,c.customer_name,p.product_name,
       p.category,s.quantity,s.unit_price,s.line_total,
       s.value_tier,s.region
FROM clean_sales s
INNER JOIN customers c ON s.customer_id=c.customer_id
INNER JOIN products p ON s.product_id=p.product_id;
%%sql
SELECT region, COUNT(*) AS order_count,
  ROUND(SUM(line_total),2) AS total_revenue,
  ROUND(AVG(line_total),2) AS avg_order_value
FROM enriched_sales
GROUP BY region
ORDER BY total_revenue DESC;

Dữ liệu mẫu gốc có 10 Orders được phân loại thành các Region: East, West, North, South, Unknown. Khi tính đối chiếu cần dùng đầy đủ dataset source, không chỉ các dòng ví dụ.

Bước 4: Apply window functions

%%sql
SELECT customer_name,order_date,line_total,
  SUM(line_total) OVER (
    PARTITION BY customer_name ORDER BY order_date
  ) AS running_total,
  ROW_NUMBER() OVER (
    PARTITION BY customer_name ORDER BY order_date
  ) AS order_sequence
FROM enriched_sales
ORDER BY customer_name,order_date;

Đầu ra vẫn 10 rows nhưng có RunningTotal và OrderSequence. Production nên partition theo CustomerID và ORDER BY thêm OrderID để tránh cùng tên/cùng ngày.

Refresh Lakehouse Tables và kiểm tra:

  • TABLE_OR_VIEW_NOT_FOUND → kiểm tra execution order và Default Lakehouse.
  • NameError → chạy lại Python dependency cells.
  • JOIN count không đúng → kiểm tra uniqueness và keys.
  • Missing gold_sales → kiểm tra write output, refresh Explorer.
  • Pipeline Notebook identity: xem quyền tài khoản chạy Pipeline; không giả định giống interactive author.
  • Cleanup đúng Workspace riêng.

Unit 7 — Knowledge check (5 câu)

  1. Run Spark SQL inside PySpark notebook? — %%sql ở đầu cell. Không dùng %%pyspark để chuyển sang SQL.
  2. Replace null discount with zero? — df.fillna({"discount":0}). dropna/isNotNull xóa rows.
  3. Replace entire Gold Delta Table each night? — Overwrite. Append làm trùng nếu chạy lại; MERGE dành cho key-matching upsert.
  4. Running Total while retaining transaction rows? — Window Function. GROUP BY giảm rows; không mặc định window luôn nhanh hơn.
  5. Compact many small Parquet files? — OPTIMIZE. VACUUM xóa old unreferenced files, ANALYZE TABLE không compact.
