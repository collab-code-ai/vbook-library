Unit 1 — Introduction

Unit này dạy gì

Sử dụng SQL-first transformations trong Fabric Warehouse để chuẩn hóa staging data, tập trung business logic, tạo các đối tượng phục vụ semantic model và nạp dimensional tables.

Nội dung chính trong unit

Nguồn staging.orders, staging.customers, staging.products, staging.dates có Orders Pending, Discount NULL, thiếu Revenue calculation, cần JOIN và các lịch sử. Nếu nhiều report tự viết SQL, một báo cáo tính gross revenue, một báo cáo trừ Discount, báo cáo khác bao gồm Pending → KPI mâu thuẫn.

Giải pháp: SELECT (query/transform), CTAS (persist results), VIEW (reuse read logic), STORED PROCEDURE (repeatable multi-step write logic), INSERT/UPDATE/DELETE/MERGE (change tables), Fact/Dimension implementation. Lakehouse SQL endpoint là read-only DML, còn Warehouse hỗ trợ ghi T-SQL theo phạm vi sản phẩm hiện hành.

Unit 2 — Transform data with T-SQL queries

Unit này dạy gì

Sử dụng SQL Query Editor, Visual Query Editor, calculated columns, null handling, joins, aggregations, window functions, CTEs và CTAS.

Query data in the warehouse

Fabric Portal → Workspace → Warehouse → New SQL query. Ngoài Portal có thể kết nối qua SQL Server Management Studio hoặc VS Code MSSQL extension bằng Warehouse endpoint và quyền phù hợp.

Warehouse → New visual query cho phép chọn bảng, JOIN, Filter/Aggregate bằng GUI và View SQL. Visual Query Editor phù hợp khám phá trực quan; code editor có kiểm soát tốt hơn với CTE, Window, DDL và Procedures.

Filter and shape data

SELECT order_id,quantity,unit_price
FROM staging.orders
WHERE status='Completed';

Calculated column:

SELECT order_id,quantity,unit_price,
       quantity*unit_price AS line_total
FROM staging.orders;

NULL handling:

SELECT order_id,
       ISNULL(discount,0) AS discount,
       quantity*unit_price-ISNULL(discount,0) AS net_amount
FROM staging.orders;

ISNULL(a,b) thay NULL của a bằng b; COALESCE(a,b,c) lấy giá trị đầu tiên không null. Chúng có khác biệt datatype/nullability ở T-SQL, cần kiểm tra khi dùng trong schema expressions.

Conditional column:

SELECT order_id,
  quantity*unit_price AS line_total,
  CASE WHEN quantity*unit_price>200 THEN 'High'
       WHEN quantity*unit_price>100 THEN 'Medium'
       ELSE 'Standard' END AS order_tier
FROM staging.orders;

Datatype conversion:

SELECT CAST(order_date_text AS DATE) AS order_date,
       CONVERT(DECIMAL(18,2),amount_text) AS amount
FROM staging.raw_orders;

Khi source có invalid strings, cân nhắc TRY_CAST/TRY_CONVERT và error handling. Dữ liệu tài chính cần precision thống nhất.

Combine data with joins and aggregations

SELECT c.region,
       COUNT(*) AS order_count,
       SUM(o.quantity*o.unit_price) AS total_sales
FROM staging.orders o
JOIN staging.customers c ON o.customer_id=c.customer_id
WHERE o.status='Completed'
GROUP BY c.region
HAVING SUM(o.quantity*o.unit_price)>500;

WHERE lọc order rows trước GROUP, HAVING lọc region groups sau aggregation. INNER JOIN có thể loại orphan Orders, vì vậy để audit unmatched customer nên LEFT JOIN và tìm keys NULL. Dimension duplicates có thể nhân bản rows sau JOIN.

Apply window functions

SELECT customer_id,order_id,order_date,
       quantity*unit_price AS amount,
       ROW_NUMBER() OVER(
         PARTITION BY customer_id ORDER BY order_date,order_id
       ) AS order_sequence,
       SUM(quantity*unit_price) OVER(
         PARTITION BY customer_id ORDER BY order_date,order_id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total,
       LAG(quantity*unit_price) OVER(
         PARTITION BY customer_id ORDER BY order_date,order_id
       ) AS previous_order_amount
FROM staging.orders
WHERE status='Completed';

ROW_NUMBER (sequence/latest record), RANK/DENSE_RANK (ranking), LAG/LEAD (prior/next), SUM/AVG OVER (running/moving aggregate). ORDER BY với tie-breaker giúp ổn định. Window giữ rows, GROUP BY gộp rows.

Structure complex queries with CTEs

WITH monthly_totals AS (
  SELECT YEAR(order_date) AS sales_year,
         MONTH(order_date) AS sales_month,
         SUM(quantity*unit_price) AS monthly_total
  FROM staging.orders
  WHERE status='Completed'
  GROUP BY YEAR(order_date),MONTH(order_date)
)
SELECT sales_year,sales_month,monthly_total,
       SUM(monthly_total) OVER(
         PARTITION BY sales_year ORDER BY sales_month
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS ytd_total
FROM monthly_totals
ORDER BY sales_year,sales_month;

CTE chỉ tồn tại trong SQL statement, không materialize mặc định thành table. Window partition theo sales_year giúp YTD reset qua năm.

Persist results with CREATE TABLE AS SELECT

CREATE TABLE gold.regional_sales_summary AS
SELECT c.region,YEAR(o.order_date) AS sales_year,
       MONTH(o.order_date) AS sales_month,
       SUM(o.quantity*o.unit_price) AS total_sales
FROM staging.orders o
JOIN staging.customers c ON o.customer_id=c.customer_id
WHERE o.status='Completed'
GROUP BY c.region,YEAR(o.order_date),MONTH(o.order_date);

CTAS tạo mới bảng vật lý và ghi kết quả. Dữ liệu nguồn thay đổi không tự làm bảng CTAS refresh; cần ETL refresh/update. Không chạy lại CREATE TABLE với tên đã tồn tại nếu chưa có chiến lược recreate.

Unit 3 — Create views for reusable logic

Unit này dạy gì

View đóng gói SQL read logic, hỗ trợ reusable transformation, abstraction và kiểm soát exposure kết hợp SQL permissions.

What views provide

  • Reusability: 15 reports dùng chung định nghĩa Revenue.
  • Abstraction: Người dùng không cần biết mọi staging tables và JOIN keys.
  • Security: Có thể chỉ expose một số rows/columns qua View, nhưng phải kiểm tra permissions/source access; View không tự thay thế RLS/OLS.

Create views in a warehouse

CREATE VIEW gold.vw_monthly_sales AS
SELECT d.calendar_year,d.calendar_month,p.category,
       SUM(o.quantity*o.unit_price) AS total_sales,
       COUNT(*) AS order_count
FROM staging.orders o
JOIN staging.dates d ON o.order_date=d.calendar_date
JOIN staging.products p ON o.product_id=p.product_id
WHERE o.status='Completed'
GROUP BY d.calendar_year,d.calendar_month,p.category;
SELECT * FROM gold.vw_monthly_sales;

Nếu muốn thay business logic, dùng ALTER VIEW hoặc cơ chế deployment phù hợp. View thông thường không lưu một bản sao dữ liệu vật lý; query đọc dữ liệu nguồn tại thời điểm thực thi.

Common view patterns

  1. Transformation View: Clean/filter + derived columns; ví dụ vw_clean_orders xử lý ISNULL Discount và NetAmount.
  2. Aggregation View: vw_customer_revenue COUNT/Revenue theo customer, có thể đọc vw_clean_orders.
  3. Denormalized View: vw_sales_details JOIN Sales, Customer, Product để expose tên/Region/Category.

Ví dụ:

CREATE VIEW gold.vw_clean_orders AS
SELECT order_id,customer_id,quantity,unit_price,
       ISNULL(discount,0) AS discount,
       quantity*unit_price-ISNULL(discount,0) AS net_amount
FROM staging.orders
WHERE status='Completed';
CREATE VIEW gold.vw_customer_revenue AS
SELECT customer_id,COUNT(*) AS order_count,
       SUM(net_amount) AS total_revenue
FROM gold.vw_clean_orders
GROUP BY customer_id;

Choose between views and tables

ViewTable
Lưu SQL definition, không lưu result thông thườngLưu dữ liệu
Thể hiện thay đổi nguồn khi query lạiCần refresh/update table
Thích hợp business logic chungThích hợp expensive aggregations/materialization
Query cost phụ thuộc underlying joinsCó thể giúp giảm repeated computation

Exam: Reusable logic + current source data → View. Expensive repeated calculations + physical persisted result → Table/CTAS + refresh. View không tự enforce referential integrity.

Unit 4 — Build stored procedures

Unit này dạy gì

Stored Procedures cung cấp reusable multi-step T-SQL với write, parameters, error handling và khả năng gọi từ Pipelines.

What stored procedures provide

Write operations, Parameters, Multi-step logic, TRY/CATCH error handling. Một Monthly Sales refresh cần xóa dữ liệu cũ của tháng và INSERT aggregate mới. View đơn thuần không làm nhiệm vụ này.

Create a stored procedure

CREATE TABLE gold.monthly_sales
(
  calendar_year INT,calendar_month INT,
  category VARCHAR(50),total_sales DECIMAL(18,2)
);
CREATE PROCEDURE gold.usp_refresh_monthly_sales
  @year INT,@month INT
AS
BEGIN
  DELETE FROM gold.monthly_sales
  WHERE calendar_year=@year AND calendar_month=@month;

  INSERT INTO gold.monthly_sales
    (calendar_year,calendar_month,category,total_sales)
  SELECT d.calendar_year,d.calendar_month,p.category,
         SUM(o.quantity*o.unit_price)
  FROM staging.orders o
  JOIN staging.dates d ON o.order_date=d.calendar_date
  JOIN staging.products p ON o.product_id=p.product_id
  WHERE o.status='Completed'
    AND d.calendar_year=@year AND d.calendar_month=@month
  GROUP BY d.calendar_year,d.calendar_month,p.category;
END;
EXEC gold.usp_refresh_monthly_sales @year=2026,@month=4;

Xóa kỳ rồi nạp lại giúp chạy lại một month mà không append duplicate; nhưng nếu lỗi giữa DELETE/INSERT có thể mất dữ liệu kỳ đó.

Production transaction / error handling:

CREATE PROCEDURE gold.usp_replace_month
  @year INT,@month INT
AS
BEGIN
  SET XACT_ABORT ON;
  BEGIN TRY
    BEGIN TRANSACTION;
    DELETE FROM gold.monthly_sales
     WHERE calendar_year=@year AND calendar_month=@month;
    INSERT INTO gold.monthly_sales
      (calendar_year,calendar_month,category,total_sales)
    SELECT calendar_year,calendar_month,category,total_sales
    FROM gold.vw_monthly_sales
    WHERE calendar_year=@year AND calendar_month=@month;
    COMMIT TRANSACTION;
  END TRY
  BEGIN CATCH
    IF @@TRANCOUNT>0 ROLLBACK TRANSACTION;
    THROW;
  END CATCH;
END;

Đây là ví dụ bổ sung hướng Production; không giả định mọi lệnh SQL Server đều được Fabric Warehouse hỗ trợ. THROW giúp Pipeline nhận failure thay vì nuốt lỗi.

Choose a loading pattern

  1. Full Refresh: Reload toàn bảng hoặc toàn kỳ; dễ hiểu, có thể tốn công lớn.
  2. Incremental Load: Xử lý chỉ những rows mới/changed từ Watermark. Phải xử lý đồng timestamp, late arrivals và chỉ cập nhật watermark sau khi load thành công.
  3. MERGE/Upsert: Matching business keys để INSERT new và UPDATE existing. Dedupe source trước khi MERGE; Type 1 overwrites không tạo Type 2 version history.
SELECT * FROM staging.orders
WHERE modified_date > @last_watermark;

Type 2 cần detect changes, close old version, insert new version, correct valid-time boundaries và surrogate keys.

Run stored procedures from pipelines

flowchart TB
    A[Copy Data to Staging] --> B[Update Customer Dimension]
    B --> C[Refresh Facts]
    C --> D[Validate Counts and Keys]
    D --> E[Downstream Analytics]

Data Pipeline orchestration gọi Warehouse procedure bằng activity/cấu hình supported, cung cấp parameters, dependencies, retries và monitoring. SQL transformation business logic vẫn sống trong Procedure.

Unit 5 — Implement dimensional tables

Unit này dạy gì

Tạo và load Fact/Dimension Tables, SCD columns, Surrogate Keys và sử dụng Table Clones cho Development/Testing an toàn.

Create dimension tables

CREATE TABLE dim.customer
(
  customer_key BIGINT IDENTITY,
  customer_id VARCHAR(20) NOT NULL,
  customer_name VARCHAR(100),
  segment VARCHAR(50),
  region VARCHAR(50),
  effective_date DATE,
  end_date DATE,
  is_current BIT
);

Fabric-specific: BIGINT IDENTITY được hỗ trợ; không dùng máy móc INT IDENTITY(1,1). Không giả định DEFAULT constraint như SQL Server ở ví dụ; cung cấp IsCurrent khi load.

Create fact tables

CREATE TABLE fact.sales
(
  sales_key BIGINT IDENTITY,
  date_key BIGINT NOT NULL,
  customer_key BIGINT NOT NULL,
  product_key BIGINT NOT NULL,
  quantity INT,
  unit_price DECIMAL(10,2),
  sales_amount DECIMAL(18,2)
);

PK/FK Fabric Warehouse dùng metadata NOT ENFORCED; không tự kiểm tra orphan facts hay duplicate keys. ETL cần validation. Grain phải được xác định từ đầu (ví dụ một line transaction).

Load dimension tables

INSERT INTO dim.customer
 (customer_id,customer_name,segment,region,effective_date,is_current)
SELECT customer_id,customer_name,segment,region,
       CAST(GETDATE() AS DATE),1
FROM staging.customers;

SCD Type 1: UPDATE giá trị hiện hành để sửa lỗi. SCD Type 2: Khi thuộc tính lịch sử đổi, đóng valid period cũ, IsCurrent=0, INSERT row mới với Surrogate Key mới. Tránh chồng lấn periods.

Load fact tables

INSERT INTO fact.sales
 (date_key,customer_key,product_key,quantity,unit_price,sales_amount)
SELECT d.date_key,c.customer_key,p.product_key,
       o.quantity,o.unit_price,o.quantity*o.unit_price
FROM staging.orders o
JOIN dim.date d ON o.order_date=d.calendar_date
JOIN dim.customer c ON o.customer_id=c.customer_id
  AND c.is_current=1
JOIN dim.product p ON o.product_id=p.product_id
WHERE o.status='Completed';

Rủi ro trong historical BI: is_current=1 dùng Customer version hiện tại, không bảo toàn Region tại lúc giao dịch. Nếu yêu cầu historical accuracy, lookup theo order_date >= effective_date AND (order_date < end_date OR end_date IS NULL). Nếu cùng source batch được INSERT lại, Fact bị duplicate; thiết kế idempotent load và lưu transaction business keys.

Use table clones for development and testing

CREATE TABLE fact.sales_dev AS CLONE OF fact.sales;

Zero-copy clone ban đầu chia sẻ dữ liệu nền, có thể thử update/delete trên clone mà không sửa bảng gốc; khi thay đổi bắt đầu phát sinh lưu trữ riêng. Tính năng Clone có giới hạn về Warehouse/Workspace và permissions, không tự áp dụng cho Lakehouse SQL endpoint.

DELETE FROM fact.sales_dev WHERE sales_amount < 100;

Exam: “Test production-like table changes without modifying original, minimize initial storage” → Table Clone. View không tạo bảng độc lập để DELETE thử.

Bước 3: Transform with T-SQL queries

Task 1: Completed Orders và các cột LineTotal, Discount, NetAmount, OrderTier.

SELECT order_id,customer_id,quantity,unit_price,
       quantity*unit_price AS line_total,
       ISNULL(discount,0) AS discount,
       quantity*unit_price-ISNULL(discount,0) AS net_amount,
       CASE WHEN quantity*unit_price>200 THEN 'High'
            WHEN quantity*unit_price>100 THEN 'Medium'
            ELSE 'Standard' END AS order_tier
FROM staging.orders
WHERE status='Completed';

OrderID 2 trong mẫu giảng: Quantity=5, UnitPrice=45, Discount=10 → Gross=225, Net=215, Tier=High. Mong đợi 11 Completed rows.

Task 2: JOIN Orders với Customers, GROUP BY Region/Segment tính Count/SUM/AVG:

SELECT c.region,c.segment,COUNT(*) AS order_count,
       SUM(o.quantity*o.unit_price) AS total_sales,
       AVG(o.quantity*o.unit_price) AS avg_order_value
FROM staging.orders o
JOIN staging.customers c ON o.customer_id=c.customer_id
WHERE o.status='Completed'
GROUP BY c.region,c.segment;

Lưu ý query này báo cáo Gross Sales, chưa trừ Discount. Production cần business KPI definition rõ ràng.

Task 3: Window ROW_NUMBER(), SUM() OVER, LAG() cho 11 completed rows, giữ nguyên detail. Task 4: CTE group Monthly Revenue rồi Window tính YTD; partition theo Year để reset YTD khi đổi năm.

Unit 7 — Knowledge check (5 câu)

  1. Running Total per customer nhưng giữ mọi Order row? — Window SUM OVER. GROUP BY gộp rows, CTE chỉ tổ chức query.
  2. Nhiều reports cùng dùng JOIN+aggregation logic? — View. View lưu reusable SQL definition, không tự materialize hay enforce FK.
  3. Procedure DELETE selected month rồi INSERT summary mới là pattern gì? — Full Refresh of a period/partition. Không phải incremental watermark hoặc MERGE Upsert.
  4. Condition c.is_current=1 trong Fact load làm gì? — Lấy current Customer version. Không lọc Orders mới nhất và không chống duplicate Facts. Historical facts cần valid-time lookup.
  5. Test table updates against Production-like data, minimal initial storage, no impact original? — Table Clone. View không cho bảng độc lập để DELETE thử, transaction commit trên bảng gốc vẫn tác động gốc.

Coverage và giới hạn

  • Đã kiểm tra cấu trúc 5 module, 39 unit, lab/case study và knowledge check theo nội dung đã được giảng trong cuộc trò chuyện.

  • Giới hạn phiên bản Markdown: Tài liệu là bản hợp nhất có biên tập từ cuộc trò chuyện, không phải raw transcript/exact export; widget tương tác đã chuyển thành câu hỏi và đáp án văn bản. Các file Notebook/SQL nguồn chính thức vẫn giữ link để có thể chạy đầy đủ.
